# M3 — eager determinization and the dense DFA

A forward DFA over the codepoint-class alphabet, built at compile time (so it
folds into the artifact), accelerating `is_match`. Look assertions (`\b ^ $`)
and all capture/span work stay on the PikeVM — D5's reverse pass and capture
pass are not yet built, so the determinizer refuses look-bearing patterns and
`Regex.find`/`captures`/`replace`/`split` remain PikeVM. This is M3's core (the
DFA, the alphabet, the budget, the downgrade), not its whole scope.

## What is built (`package/Dfa.roc`)

- **Determinization** over the trie's atoms: states are epsilon-closed pc-sets
  (split/jmp/save followed; look excluded), transitions keyed by class. The
  start closure is unioned into every transition, so the DFA is **unanchored**
  (D2) — `is_match` needs no per-position restart.
- **Dense table**: `state*n_classes + class -> state+1` (0 = dead), plus an
  accept flag per state.
- **Budget / downgrade (D10):** `max_states = max_artifact_bytes / (n_classes*4)`
  with the 256 KB provisional budget. `Dfa.build` returns `Err(TooBig)` (state
  cap exceeded) or `Err(HasLook)` (look assertion); either downgrades to the
  PikeVM. The outcome is recorded in `Regex`'s `engine : [Pike, Dfa(...)]` field
  (D10's observability), set at compile time.

## Verification

Differential harness (`tools/diff`) now checks **both** `find_all` (PikeVM) and
`is_match` (DFA when look-free) against the Rust crate: **1431/1431 agree.** A
focused probe confirms engine selection — look-free patterns (`[a-z]+[0-9]+`,
`foo|bar|baz`, `\w+@\w+`, `(ab)+c`, `a.*z`, `\p{Greek}+`, `(?i)hello`) build a
DFA and agree with the PikeVM oracle; `\bcat\b` and `^abc` fall back to `pike`
and are still correct.

## Gate

Three DFA-engine patterns (`[a-z]+[0-9]+`, `foo|bar|baz|qux`, `\w+@\w+`) embed at
**315,536 B / ~105 KB per pattern** (NFA + trie + DFA table). The DFA table
folds into the binary alongside the NFA. smoke still 21/21.

## Not yet in M3 (honest)

The reverse DFA and the three-pass `find` (D5) — `find` is still PikeVM; the
DFA accelerates only `is_match`. Unicode `\b` in the DFA (the codepoint
look-behind machinery the codepoint study validated). Byte-class stride
minimisation and `U16` state ids. Per-object artifact split. These are the
remaining M3 work; the determinizer, alphabet, budget and downgrade are done.
